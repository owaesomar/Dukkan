# Security baseline and open work

Implemented: environment-based configuration; production checks for HTTPS CORS origins, remote database/Redis hosts, and an S3 bucket; request IDs in structured logs; sanitized server errors; database/Redis readiness; no automatic schema creation or SQL echo; Argon2id password hashes; opaque hashed, expiring, revocable sessions; HttpOnly/SameSite session cookies with production Secure setting; CSRF cookie/header validation; Redis-backed rate limits; sanitized request-validation errors; active store membership and role checks; tenant-scoped catalog/inventory/order/analytics/subscription queries; composite tenant foreign keys; stock adjustment and checkout reservation row locks; strict image size/type allowlist; private S3 object uploads with short-lived signed read URLs; hashed order tracking tokens; checkout idempotency; separate explicit platform-admin grants and audited events; cross-tenant/concurrency tests; locked dependency installation; and CI dependency audit jobs.

Not yet implemented or externally verified: image re-encoding/metadata stripping, email verification, password reset, MFA, session/device management, payment webhook verification, PostgreSQL RLS, production error/metrics monitoring, automated secret rotation, offsite backup scheduling/retention, and a provider-specific deployment/rollback rehearsal. The Node advisory endpoint could not be reached from the isolated development environment; Python dependency auditing reported no known vulnerabilities. Treat the product as an early SaaS foundation; a local restore rehearsal does not establish production readiness.
